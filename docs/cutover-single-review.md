# 原本SELECT遮断・安全停止のLABレビュー

本番実行は禁止。`02-cutover.sql` は成功すると原本SELECTの権限を変更する単一DO文で、`run_cutover := false` が初期値。`03-safe-stop.sql` は遮断後専用で、`run_stop := false` が初期値。停止はRPCの一般利用を閉じ、原本SELECTが既に閉じていることを検査する。旧原本SELECTを復活させない。どちらも別途承認・直前監査・全LAB検証が必要。

旧 `admin.html` は原本を直接読むため、原本SELECT遮断後は試合の読み込みができない。運営画面の再開には別途安全な管理者認証と権限設計が必要。外部利用・古いページ・キャッシュから原本を読む経路も事前に確認する。

検証用SQLは security LAB マーカーと架空テーブルを使用し、通常系は最後にROLLBACKする。ガード・意図的な異常系は実行エラー後、新しい接続から残留確認と既存データ・権限の比較を実施する。いずれも本番では実行しない。

正常系 `lab-normal.sql` は17件の公開、非公開遮断、両ロールの原本遮断、停止、元データ・既存LAB設定の比較を確認。`lab-cutover-guard.sql`、`lab-stop-guard.sql` は NOT APPROVED、`lab-cutover-failure.sql`、`lab-stop-failure.sql` は意図的な例外が期待値。失敗または予期しない結果では停止する。

本番実行後に問題がある場合は、旧ページへ戻さず、別途承認のうえ停止版の適用を検討する。停止中は試合一覧・視聴が使えない。ブラウザーやCDNのキャッシュ、GraphQL・外部サイトや非管理者の実JWT検証は別途確認する。

## 実行時間の上限（LAB再検証中）

単一DO文の中で `statement_timeout` を設定しても、既に始まったDO文の制限にはならない。遮断・安全停止の各DOは、開始前に `statement_timeout` が1〜30000msであることを内部で検査し、条件外なら変更前に例外で停止する。`lock_timeout` はDO内で5秒に設定する。

将来の本番作業は、別途承認・直前確認・検証完了後に限り、同一トランザクションと同一接続で、DOの前に `SET LOCAL statement_timeout = '30s'` を設定する方法を検討する。SQL Editorの実際の実行単位による動作はLABで確認する。複数文を別々に選択して実行せず、異常時は中止して新規接続で状態を確認する。事前設定が効かずタイムアウト条件が確認できない場合、SQLは実行準備未完了。
