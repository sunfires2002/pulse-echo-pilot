# 公開関数準備：独立確認と準備段階の停止

本番SQLの実行は別途承認が必要。接続先はSupabase画面のプロジェクト名と参照IDを運営者が目視で照合する。SQLの構造ガードは接続先を保証しない。

## 検証用Supabaseでの別接続テスト

1. `sql/prepare-stage-review/01-baseline.sql`を実行し、結果を保存する。`goods_metadata:null`はテーブルがないことを表し、実テーブルの権限検証ではない。
2. `07-commit-lab-setup.sql`で専用の架空テーブル・ロール・関数をCOMMITする。検証用マーカーと名前衝突を確認する。テスト中は架空オブジェクトが残る。
3. 新しいSQL Editor接続で`08-separate-connection-audit.sql`を実行。17公開、1非公開、返却12項目、動画21項目、無効0、匿名原本SELECT維持などを確認する。SQL Editorの新規タブだけではサーバー接続のPID差を保証できない。
4. `09-cleanup-test-only.sql`で架空オブジェクトを撤去。失敗すればROLLBACKし、エラーを調査する。既存オブジェクトへのCASCADEは禁止。
5. 独立した残留確認と`01-baseline.sql`を再実行し、事前と一致することを確認する。

2026-11-05: 架空の準備をCOMMIT後、別SQL Editorで確認SQLが成功し、撤去後の対象残留0、元のRLS・データ・ACL・スキーマACL・ロール所属の比較値が一致。実際に接続PIDが別であることは未検証。通常・異常系の停止リハーサルおよび異常後残留0を確認。

## 本番準備段階の停止案

`03-prepare-safe-stop.sql`は実行禁止ガード付きの案。旧画面が利用する元テーブルSELECTを維持し、公開関数の一般実行、専用ロールのSELECTと直接USAGEを停止する。新規関数・ロール・ポリシーは残す。PUBLIC由来のスキーマUSAGEまで除去するものではない。新関数の別経路、既存の継承、ロール所属が想定と異なれば停止し、再検討する。

関数所有者権限のためpostgresから付与元を指定して一時的にSET権限を付与し、同じ付与元だけをREVOKEする。既存所属の全属性の前後一致を確認する。既にpostgres付与の同一所属がある場合は停止する。旧SELECTを遮断する`production-public-read/03-safe-stop.sql`とは異なり、準備段階専用。

実行後の本番監査`02-independent-review.sql`は管理者権限での集計であり、匿名・非管理者JWTによる実HTTP検証の代替ではない。旧匿名SELECTが残る準備段階は原本・非公開情報の保護完了ではない。キャッシュや過去の公開データを回収できない。事前事後の照合には基準値が必要であり、MD5は変更検出用であって暗号学的な改ざん証明ではない。
