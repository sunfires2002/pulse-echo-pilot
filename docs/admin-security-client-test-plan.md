## 3. 実APIのAuth/RLS試験（変更試験の確認後）

```sh
python3 /Users/momo/.codex/visualizations/2026/10/25/01a170ab-dbd7-7d13-b1ce-7dd62b47f5b9/admin-safety-lab/tools/run-admin-security-lab-tests.py --run
```

実行時に検証用project refを再入力し、管理者・非管理者のメール/パスワードを対話入力する。パスワードをコマンド引数・ファイルへ保存しない。必要な環境変数は子プロセスだけに渡し、表示しない。Mac Terminal以外の非対話パイプ入力では実行しない。

- トークン取得後、管理者UUIDが設定と一致し、非管理者UUIDが異なることを確認してから試合を作る。
- `admin-rls-lab-<実行ごとのUUID>-...` の架空行だけを作成・変更・削除する。
- 管理者が公開・非公開の架空試合を作成できること。
- 匿名/非管理者は公開行だけ見え、非公開行は直接ID指定でも返らないこと。
- 匿名/非管理者のINSERT/UPDATE/DELETEが拒否され、元データが不変であること。
- 管理者だけUPDATE/DELETEできること。updated_atがDBで更新され、古い版でのUPDATEは0行となること。
- テスト後は、この実行で作ったプレフィックスの行だけを片付ける。既存行は削除しない。

RLSの拒否はHTTPエラーだけで判定せず、更新0行と管理者によるデータ不変確認も使う。SQL Editorの管理者権限は試験の代用にしない。

## 4. 実LAB画面での確認

- 管理者：登録→編集→撮影/編集/確認→公開/停止→削除。対象の1件だけ変わる。
- 非管理者：ログインできても管理操作を許可しない。直接API拒否は前項で別検証。
- 一覧選択/再読み込みでPOST/PATCH/DELETEが発生しない。
- 保存拒否で「保存完了」とならない。拒否前後の内部状態とDBを比較する。
- 2タブで同じ版を読み、先の保存後に後の保存が競合で止まる。
- ログアウト後、画面の一覧/入力/認証情報が消え、保存できない。
- 保存要求がサーバーで処理された後のログアウトは、その処理を取り消す保証がない。結果不明時は読み直し、自動再送しない。
- 本番ホストへのHTTP/WS 0件をネットワーク記録で確認する。トークン入りHARは保存/共有しない。

## 5. 認証期限切れは別に記録

ローカルの模擬期限切れや、通信を401へ置き換えた試験だけで「実JWT期限切れ確認済み」としない。

まずログアウト、無効セッション、通信拒否時の保存停止・成功誤表示なしを確認する。
実JWT期限切れは検証用トークンの自然な有効期限を使い、旧トークンの拒否、SDKの更新成功/失敗を別々に確認する。パスワードやトークンの値は記録せず時刻・状態だけを記録する。本番や検証プロジェクトのJWT期限設定を勝手に変更しない。

ログアウトだけで発行済みアクセストークンが即時失効したとは判断しない。期限待ちが必要なら未完了として区別する。

## 合格の判断

API試験・画面試験・実JWT期限切れを分けて報告する。接続前の静的/ローカル検査は、実Auth/RLS合格とは扱わない。
本番のRLS・GRANT・Auth・データには変更しない。検証プロジェクトの設定変更が必要になったら、実施前に内容を確認する。
